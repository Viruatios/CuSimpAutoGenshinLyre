# 简化自动原琴 - CuSimpAutoGenshinLyre

一个BetterGI的JS自动化脚本，基于提瓦特钓鱼玳师和半江残秋老师的AutoYuanQin。

## 主要改动：读谱规则极度简化。以及播放调度模型的修改。

### v0.1.0 修改后的读谱规则

1. 只对于“弹奏琴”有效，只对于“键盘谱”有效。不支持其他类型。
2. 定义：每个音符为一个基本单位，它可能是“单个按键”、“同时按下按键”或是“琶音按键”，基本单位之间以“空格”分割。
3. 定义：两个“/”符号之间的按键是一拍，即不同拍之间以“/”分割；一拍的时长由BPM决定；每一拍内的“基本单位”均分这一拍的时长。
4. 定义：单行之中的按键视作一小节，即不同小节之间以“\n”分割。
5. 规定：对于每个处于两个“空格”之间的“基本单位”，单个字母视作“单个按键”，一个“()”内的所有字母视作“同时按下按键”，多个字母则视作“琶音按键”。
6. 规定：对于每一拍内，只有上一个“基本单位”的持续时长结束，才能演奏下一个“基本单位”。该等待规则不仅作用于每一拍之间，也作用于每个“基本单位”之间。
7. 约定：若两个“空格”之间没有字母，则视作“休止符”；不考虑延音。
8. 约定：在分割音符时，“/”和“\n”视作具有“空格”的同等效果，均为分割符号；但是，当且仅当相邻的两个分割符号为“/”和“\n”时，规则6不生效。
9. 约定：对于“琶音按键”内的多个字母按键，每个字母按键均分该“琶音按键”的时长。

### v0.1.1 对播放调度模型的修改

原模型为何不符合规则6：

1. 对每个音符调用一次异步 notePlay，但不等待它结束。这样“下一个基本单位必须等上一个基本单位结束”只靠 offset 间接实现，不是强约束。只要计时抖动或调度顺序变化，就可能出现时值不符合预期。
2. 两个协程都在操作同一个键。例如前一单位末尾 keyup 与下一单位开头 keydown 在同一时间点附近触发时，若前一单位的 keyup 晚到，会把下一单位刚按下的键立即抬起，导致后一个单位实际时长变短。
3. wait 和 time 都做 Math.floor，单位越细（例如一拍内分得越多），累计截断误差越明显。结果是“单位结束时间”会早于理论值，听感上就是持续时长不准。
4. 结论：核心的问题在播放调度模型：当前是“按音符并发定时”，不是“按基本单位串行执行”。这会直接破坏“上一个基本单位结束后再进入下一个”的强等待规则。解析侧（offset、unitDuration）大体是对的，但会被并发竞态和取整误差放大。

改动：

1. 序列化结构升级为“基本单位序列”

- `keySheetSerialization` 现在输出：`[小节拍数, ...基本单位]`。
- 基本单位结构为：`{ kind: rest|single|chord|arpeggio, keys: string[], time: number }`。
- 这使播放层可以直接按单位串行执行，不再依赖“按音符并发 + offset”间接对齐。

2. 播放调度模型重构为单位时间轴串行驱动

- 每个基本单位执行前必须等待到其开始时刻，执行完成后才进入下一个单位。
- 调度使用 `await` 串行推进，从根上保证“上一个单位结束后再进入下一个单位”。
- 同键位的 `keyup/keydown` 竞态被消除，避免单位边界误抬键导致时值缩短。

3. 时值对齐策略调整

- 改为基于绝对时间点对齐（`sleepUntil`）并使用 `Math.round`，降低累积截断误差。
- 每小节结束会对齐到理论小节终点，减少长曲播放漂移。

4. 行为结果

- 串行、和弦、琶音与休止符都在同一时间轴模型下执行，时值一致性更高。

### v0.1.2 读谱细节优化（让我头疼了好久才发现）

- 如果一拍的内容编写为 "A B /"（注意 B 后面有一个用于排版的空格），按 / 首先被分割为 "A B "（末尾多一个空格）。
  当对 "A B " 执行 .split(' ') 时，会被分割为 ["A", "B", ""]。此时 units.length 变成了 3（而不是预期的 2），多出来的 "" 触发了定义的“两个空格之间视为休止符”的逻辑。这导致原本各占 1/2 拍的 A 和 B，变成了各占 1/3拍，并在结尾多出了 1/3拍的休止符。
- 通过将每一拍的字符串在切割前进行 .trim()（去除头尾排版多余空格）解决了该问题。不仅去除了该副作用，而且仍然完美支持内部连续空格（例如 "A B" 中间连续两个空格）产生休止符的逻辑。

## 播放演奏脚本

1. 在全自动 - 调度器中 新建配置组/选择已有的组 将*CuSimpAutoGenshinLyre*添加至配置组中
2. 右键原琴 - 修改脚本自定义配置 按照说明填写
3. 点击运行开始播放音乐

## 曲谱文件位置

1. 所有的曲谱文件应放置于 `CuSimpAutoGenshinLyre/assets/score_file` 路径下

## 文件结构

一个标准的曲谱.json文件的基本结构如下(五线谱制谱器/简谱制谱器格式)：

```json
{
	"name": "",
	"author": "",
	"instrument": "",
	"description": "",
	"type": "",
	"bpm": "",
	"time_signature": "",
	"composer": "",
	"arranger": "",
	"notes": ""
}
```

**注意**：以上代码中仅 : 右侧的**双引号内**的部分可以更改, 具体的曲谱格式请参考 `/assets/tutorial_file` 路径下的 `example.json`

### 字段说明

`name`: **必要键值** 曲谱名

`author`: **可选键值** 录谱人, 制作这个.json曲谱的作者名

`instrument`: **可选键值** 此键值对用于建议用户的乐器使用

`description`: **可选键值** 可以随意填写关于该曲谱的描述信息

`type`: **必要键值** 决定曲谱的解析方式, 合法的值有`yuanqin`(默认值, [五线谱翻谱器](#五线谱翻谱器)) `midi`([MIDI制谱器](#MIDI制谱器)) `keyboard`(你在网上看到的琴谱格式与此相似)

`bpm`: **必要键值** 曲谱的BPM (Beats Per Minute)

`time_signature`: `yuanqin`的**必要键值** 拍号, 例如 3/4 代表 以四分音符为一拍每小节三拍(被设为一拍的音符仅支持2的幂)

`composer`: **可选键值** 曲师

`arranger`: **可选键值** 谱师

`notes`: **必要键值** 曲谱内容,该部分请参考改动后的读谱规则

### 代码美化

曲谱JSON文件的"notes"的值视作一个字符串, 在这个字符串内仅可以使用**换行符**美化代码, 通过这种方法可以使用记事本等软件从.json文件中获取带有换行的曲谱代码(**notes内的换行符不会被读取执行**，所以不用担心多加的换行符会影响脚本读取)
